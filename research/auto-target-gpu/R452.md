# R452: measure residual spikes after R451 weighting

User reports R451 speckles unchanged. Nine R451 target snapshots were valid;
later bounds contained the historical R447 strongest hit. This proves neither
current spike coverage nor visible improvement. R451 is a failed visual test.

R452 keeps the rendering estimator and learner. Five bounded 512x512 all-pixel
snapshots record same-sample raw RGB, weighted RGB, dominant weighted endpoint,
material, ray index and p/q. Both peaks include final fade/divisor; dominant
fraction uses weighted peak / weighted sum luminance. Exact frozen input bounds
are copied alongside each output-bound snapshot. No additional rays, clamps,
blur, history change, point/spotlight dimming or performance optimization.

Implementation uses a disjoint tail of the training UAV; bit16 in existing
capacity constants enables it, low16 remain the original learning count. Builder
reads only that count. A 64-byte pixel ABI uses two 32-byte training slots.
Every admitted ROI pixel first clears its record, including invalid receivers.
Separate completed-owner readback is retained through both queue submissions.
The existing 64MiB owner pool accounts for both GPU/readback storage. At maximum
ROI the audit adds 32MiB on five invocations; no readback CPU/GPU wait occurs.
CPU neighborhood reduction and copies can perturb frame pacing.

Logs count all ROI outliers >10x 5x5 median and luma>.001 and retain 12 strongest.
These are not skin-only labels and raw guided sums are not native baselines.
Readback is pre-RR evaluator output, not an assertion of downstream RR equality.
This measurement distinguishes remaining heavily downweighted spikes from spikes
whose dominant ray is unhelped/amplified, with matching endpoint and input bounds.
It does not by itself identify exact per-light shadow/intensity operands.

Validation: CPU fixture checks ROI placement, surviving downweighted outliers,
unhelped outliers and invalid clearing. GPU fixture covers every pixel of an
irregular 19x17 ROI, verifies all ABI fields, disabled no-write behavior, and
both prefix/suffix guards. Existing target/sampler/roots/training/lifetime tests
remain required. No in-game speckle fix is claimed.
