# R455: visible movable region and user-armed capture

User requested a movable square showing the exact capture area. Adds a transparent,
non-activating Windows outline and status label in the existing50ms UI thread.
Alt+arrows moves the normalized center in preview/completed states; F7 freezes it,
counts down5s, then starts the existing five-pair schedule. No Ctrl input. Supports
rearming after ten completed readbacks. Captures no longer start before positioning.

Shared integer ROI policy drives overlay placement and per-invocation CPU origin.
That immutable origin is encoded into unused bits of the existing four root
constants: step low9 bits, X bits9..22; capacity low16, audit bit16, Y bits17..30.
No root-signature expansion. Training masks its fields before tile indexing.
Shader audit writes use the supplied origin, not the former hard-coded left-center.
C++ validates origins against dimensions; shader rejects invalid ranges. Owner
retains ROI and capture request ID through completion; logs use owner coordinates.
Pair cache additionally rejects different origins and resets between captures.

UI border scales GI input boundaries into the current game client area and is
hidden when not foreground/minimized. This Windows overlay requires windowed or
borderless presentation; it is not burned into the GI/RR buffers. No screenshot
capture is added. R453 sampling/lighting estimator and guide lifetime unchanged.
