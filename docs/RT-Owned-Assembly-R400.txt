repeated geometry/material preparation inside native static instanced groups.
It prepares the first instance, then reuses its shared records while writing each
remaining transform and contribution index. Record counts and order stay native.
Reuse ends at the group boundary. Nothing is cached across frames or update calls.

Reuse requires the verified static provider and sufficient existing capacity for
the entire group. Unknown/skinned providers and growth cases use the existing path.
Native readiness checks, dynamic updates, material-ID patching and AS builds remain.
PTLAS stays OFF. No FPS gain is claimed before in-game measurement.

Build gates include 16,384 original-machine-code assembly comparisons, including
4,096 repeated-assembly/batch cases, plus the existing selection and outer-loop
comparisons. Batch cases check transforms, flags, prefix wrap, output bytes/order,
capacity flags, allocator fallback and side-effect-free rejection.
