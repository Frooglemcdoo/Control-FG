# R149 — RT diffuse-GI baked-brick comparison

R148 supplied 316 complete, SHA-256 verified shader records (one skipped observation). The old 17040-byte baked-GI pixel shader was absent. That dependency prevented the R147 comparison modes from becoming available; bypassing the readiness check would not have produced a valid comparison.

Two bound compute shaders, 32888 and 35144 bytes, sample six GI-brick textures while computing RT diffuse GI. Their exact identities and original bytes are in assets/baked-gi-rt. R149 replaces only those six texture sample instructions with zero-result instructions, preserving destination masks and instruction lengths. All other bytes except the DXBC checksum remain unchanged. Direct-light calculations, hit outputs, bindings and subsequent GI filtering remain intact.

Baked GI Off and GI + RR Off now use these exact-hash compute variants. Both variants must be prepared successfully before either mode is enabled. Other shader versions are not patched heuristically. Default rendering, corrected spotlight shadows and exposure behavior are unchanged. This is a diagnostic comparison, not a confirmed fix for room-transition shadow loss, and does not remove baked illumination from reflections, fog or every rendering path.

## Test

1. Close Control and copy the package beside Control_DX12.exe, preserving installed NVIDIA runtimes and ControlFGStreamline.
2. Keep the same graphics settings, with RT Contact Shadows on and samples at 1.
3. Open F10. Compare Default, Baked GI Off, RR Off and GI + RR Off in the affected room. Allow several seconds for each mode to settle, then repeat the doorway movement. No restart is needed between modes.
4. Record one video, return to Default and Save Log. Send the video and log. If a mode remains unavailable, Save Log includes shader identities and bytecode; no F9 capture is required for this test.

## Validation and limits

The generator checks input hashes, exact instruction layouts, six unique brick samples, unchanged resource bindings and byte-for-byte preservation outside the edits/checksum. The Windows test compares the C++ runtime patches against generated bytes, rejects changed instructions, disassembles both native/patched variants and creates their compute PSOs on WARP. Readiness tests reject incomplete variant sets. These checks do not establish gameplay correctness or GPU performance; the in-game comparison remains necessary.

R148 bounded shader logging and R146 asynchronous capture remain available. Large capture packaging stays below 200 MB per part. No render-thread file writes or GPU waits were added.
