# R214 — Current-frame GI outlier cleanup

R213 isolated the tradeoff. The user reports Both clean but ghosting; Temporal Only heavily speckled; Spatial Only free of speckles but boiling; Clamp Only free of ghosting/boiling with minor speckles. The 11:11 log confirms every sampled stage applied, with 27,016 RR successes and zero failures. Clamp Only is the experimental starting point for R214.

Default: Native Blend with GI: CLAMP ONLY and CLEANUP: ON. Keep RR ON, FG OFF, SPEC Native and hit distance OFF. Compare CLEANUP ON versus OFF in F10, waiting ten seconds after each switch and repeating the same movement. OFF is exactly the R213 Clamp Only shader/policy. Inspect the projector room speckles, moving carpet, dark shadows, and small bright lighting details. Save one F10 log while RR is enabled. The original four GI comparison modes remain available; cleanup applies only to Clamp Only and displays N/A elsewhere.

The cleanup shader retains the native current-frame luminance clamp and color normalization, with zero temporal history and zero native spatial passes. Before scaling the current sample, it samples four axial neighbors at LOD0, finds their second-largest luminance, and limits current luminance to at most 1.5 times that value plus 0.002 in shader radiance units. One bright neighbor cannot inflate the bound. Two supporting neighbors permit bright lines/edges; uniform bright regions are unchanged. RGB is scaled together using the original native normalized color, preserving its chromatic ratios. This is a local current-frame limit, not the native multi-pass spatial filter.

The variant adds four texture reads to the original shader. It omits the R212 filtered-neighborhood history-color instructions, which are unnecessary with zero history. Native temporal resource bindings/instructions remain for compatibility, but their blend coefficient is zero. Existing R212 and R213 comparison bytecode remains unchanged. No engine object clones, history clears, CameraCut overrides, extra render passes or resource providers are introduced.

A third immutable GPU PSO uses the same root signature and bindings. The cleanup request is atomic, latched once for the eligible native GI filter call, and restored as thread-local scope state in finally. Logs identify stage, outlier request applied to that scope, effective spatial passes, pipeline replacement success and RR status. If applied=0, the requested shader was not used; do not interpret that interval as a successful cleanup test. RR OFF and other lighting modes retain their existing paths.

Validation includes source SHA lock, exact native instruction preservation around one insertion, original non-SHEX chunks/bindings, zero temporal coefficient, actual WARP shader compilation/dispatch/readback, and native pipeline restoration. GPU cases cover isolated bright samples, adjacent bright pairs, thin bright lines, bright region edges, uniform bright radiance, black radiance, and the previous history/clamp controls. Runtime scope tests cover all stage and toggle combinations, validation fallback and exceptions.

The threshold is experimental. A valid isolated light feature without neighbor support can also be attenuated; test fine detail and brightness in game. The synthetic tests demonstrate the stated algorithm, not guaranteed scene quality or performance. Projection rays, MAP GUARD OFF, angled reflections and accepted R205 settings are retained. Production unchanged.
