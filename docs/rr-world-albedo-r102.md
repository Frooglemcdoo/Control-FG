# R102: textured world diffuse guides for RR

## Confirmed R101 evidence

The supplied R101 archive contains 19 complete shader pairs, including 11 Standard-material pairs with four distinct candidate pixel shaders. All 11 Standard vertex shader pairs match byte for byte. All four candidate pixel shaders pass the production single-target contract parser. Capture frames 7952 and 7953 are consecutive, have reset=0, successful RR evaluation and captured output. The session reports 7,550 successful RR evaluations, zero RR failures/rejections, and 7,346 validated native GI filter calls.

In frame 7952, the painting interior rectangle x=1300..1849, y=560..949 and wall rectangle x=1000..1799, y=200..399 both have exactly one diffuse RGB value: (0.054901123, 0.054901123, 0.054901123). Their raw replay RGB is uniformly (-1,-1,-1), the uncovered sentinel. Thus the affected surfaces are receiving the flat material fallback rather than textured diffuse reflectance. This confirms a guide gap, not that it is the sole cause of stationary oversharpening.

## Audited shader semantics

All four variants read material ID from b0, material Part3 (336-byte stride) from t0 space0, and bindless material textures from t0 space1 using sampler s19 space1. They sample base texture at materialID*35 and multiply by tint at byte offset 52. The simple variant outputs this product. The detail variant additionally multiplies by a scalar from texture slot +16 and the native detail parameters. The layered variant blends base and texture slot +12 with material/vertex blend parameters; the fourth variant combines detail and layering. None reads lighting, shadows, RR history or the framebuffer. The original texture arithmetic, texture decoding through native views, UVs and vertex shaders are retained.

Exact SHA256 identities and captured bytes are in tools/fixtures/rr-world-albedo. Runtime admission compares the entire candidate bytecode, then retains the existing byte-identical VS and binding/target validation. Unknown Standard variants, other families and failed clones are not admitted by this change. Character/Hair admission and replacements remain unchanged.

## New live comparison

Install with the game closed. Keep RR ON. At the affected wall/painting compare GI FILTER (R100/R101 baseline) and WORLD ALBEDO, waiting 10 seconds while stationary in each. Both retain native GI filtering, centered selected-spotlight rays and native shadow filtering. No restart between comparisons. SAVE LOG once; send the Lighting-R102 log and comparison screenshots. F9 is optional only if another buffer capture is needed.

WORLD ALBEDO replaces the inactive DIFFUSE FILTER UI button. It replays the four audited Standard albedo variants alongside the existing character/hair draw set. No lit-color substitution, blur or sharpening adjustment is applied. RR history resets when the actual current-frame world-guide binding changes, including return to fallback; a replay prepared under a different world-guide mode is not bound. world_albedo_bound counts frames with accepted Standard batches in a current-frame replay actually copied to the guide input, not proven per-pixel coverage. world_albedo_rejected counts unknown or unavailable Standard replacements after structural validation.

Native RGB instructions and bindings are byte-preserved; a single final mov forces replay alpha to 1 so world materials cannot impersonate the negative private hair tag. Only the mod's cloned replay shader records use this bytecode. A fixed 64-record cache avoids recurring allocations and never overwrites records referenced by the engine. At capacity, unknown records retain the prior fallback. GPU work increases with visible admitted Standard batches; measure performance in the scene.

## Validation and limits

Local tests verify exact byte admission and mutation rejection, unchanged RGB instructions/bindings, alpha-only output, checksum and production contract parsing, bounded clone ownership/failure behavior and mode isolation. Windows CI additionally disassembles the generated bytecode using D3DCompiler, builds the proxy, and runs baseline/character/menu/GI and WARP shadow routing tests. All 14 shadow shader assets remain exact R97; character/hair shader assets are unchanged. Visual improvement, full scene coverage and in-game performance require the R102 comparison; no visual fix is claimed before that test.
