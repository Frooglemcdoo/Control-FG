CONTROLTOH R392 - RR performance comparison

Install this complete build over your existing ControlTOH installation.
Keep RR ON and turn Frame Generation OFF. Load a quiet problem area with Jesse
visible. Keep resolution, DLSS, VSync and frame cap fixed; a limiting frame cap
can hide performance differences. Choose an uncapped comparison if practical.
Open F10 and click PERF COMPARE. Return to the game and remain stationary.
The capture arms for five seconds, then automatically switches nine conditions.
One beep starts each measured interval; two beeps mean packaging is finished.
Allow about three minutes and keep the game focused. Your previous rendering
settings are restored before packaging. Explorer selects the resulting ZIP.

Conditions: native RR; native RR with 4 GI samples; Owned GI raw at the native sample count; plus enhanced
lighting; plus RELAX; plus character filtering; full features (including both volume filters);
full repeat; native repeat. Each condition warms for 5 seconds and measures 12.
The native baseline uses the same mod RR integration, not an unmodified game.
Clamp and unrelated settings are fixed; reflection sample policy is Native.

Report includes frame-time percentiles, average FPS, slowest-1-percent FPS,
selected GPU stage durations, CPU recording/API spans, path counters, settings
and repeated-condition drift. Missing coverage and failures remain visible.
GPU stage spans are not total GPU frame time; nested spans must not be summed.
The test does not capture textures or large shader inventories. Instrumentation
is disabled until clicked and disabled on completion or cancellation.
Alt-tabbing cancels the comparison, restores settings and packages partial data.
Send the small ZIP under LOCALAPPDATA/ControlFGProbe for analysis. The existing
CHECK SETTINGS and other on-demand capture buttons remain available.

R388 reuses two RELAX upload buffers after GPU completion AND command-list reset.
Eight retired work bundles are cached; epoch changes discard the cache. Shader
code, denoiser parameters, GI samples and accepted quality remain unchanged.
GPU timing samples every 64 Presents and excludes unrelated compute/ray work.
Lighting coverage uses actual enhanced shadow-ray dispatches instead of volume
bindings. Missing phase timings or coverage mark the capture incomplete.

R389 adds bounded, on-demand RELAX failure records to relax-failures.csv. The
report identifies camera-frame/view changes, input authentication, matrix or
jitter rejection, pending submission, and resource/recording exceptions. It
includes frame and Present numbers plus guide and pending-recording context.
This locates the intermittent raw fallbacks seen in R388; it does not claim
those fallbacks are fixed. R388 buffer reuse and quality settings are retained.
No full-screen captures or continuously running rejection inventory is added.

R390 reserves RELAX descriptors from the actual prepared dispatch plan rather
than the maximum possible pass count. Clear/restart frames still receive their
full required range. Allocation completes before any filter commands; failure
cancels the prepared history and forces a safe restart on the next attempt.
Native heap identity, bounds, prefix and overlap checks remain enforced. Failure
reports now distinguish rollover, capacity, handle, range and overlap rejection.
Windows GPU tests cover exact-size steady-state reservations, larger restart
plans, rejected allocations, undersized/wrong-heap results and recovery, plus
existing brightness, outlier, light-removal and moving-surface checks.
This reduces descriptor pressure; in-game capture must verify remaining fallbacks
and performance. No shaders, sample counts or denoising parameters are changed.

R391 handles native descriptor-heap rollover with a private fallback heap for
RELAX and receiver export. Normal allocations continue using the bound native
heap. Both compute bindings and graphics descriptor tables are restored after
private-heap work. Two graphics binding setters are tracked for state restoration;
this is rendering-state bookkeeping, not shadow inventory or capture monitoring.
Unknown graphics state rejects heap switching rather than guessing bindings.
RELAX private heaps stay with their work bundle and are reused only after GPU
completion AND command-list reset. Receiver fallback work is likewise retained
through completion/reset. Shaders, samples, history settings and output formats
remain unchanged. R390 exact-size reservations remain in place.
Validation alternates native/private RELAX heaps and verifies a real graphics
draw plus compute dispatch immediately afterward, alongside the existing 128-frame
brightness, moving-surface, outlier, light-removal and buffer-reuse checks.
Microsoft descriptor heap contract: https://learn.microsoft.com/en-us/windows/win32/direct3d12/setting-descriptor-heaps
In-game performance and rollover recovery still require the PERF COMPARE run.
Successful RELAX and receiver heap recoveries are counted only during an active
settings/performance capture and included in SUMMARY.txt.

R392 uses the native GI sample count for Owned GI on startup, RR enable and
settings reset. Owned GI, RELAX, clamp 60 and lighting fixes remain active.
Native means the game-supplied count, not a hardcoded one-ray override.
All Owned PERF COMPARE phases now use native samples. The explicitly named
native_rr_4_samples phase remains a four-sample diagnostic reference only.
No filter parameters or shaders changed; lower-sample visual quality requires
in-game comparison, particularly motion, disocclusions and changing lights.
